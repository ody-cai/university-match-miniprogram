# 升学规划小程序

个人分享的选校参考小程序：面向国际课程学生（AP / A-Level / IB）。输入成绩 → 匹配院校 → 查看详情 → 收藏。

---

## 一、运行

1. 打开**微信开发者工具** → 导入项目
2. 目录选择 **仓库根目录**（本 README 所在目录，不是 `miniprogram/`）
3. AppID 用**正式 AppID** `wx3946283e81d38ef9`（仓库根的 `project.config.json` 已配好；
   其中 `miniprogramRoot: "miniprogram/"` 指向小程序源码，`cloudfunctionRoot` 指向云函数）。

> ⚠️ **项目根必须选仓库根，别选 `miniprogram/`**。开发者工具的项目根 = `project.config.json` 所在目录，
> 而它的「版本管理」只认**位于项目根**的 Git 仓库（不会往上找）。根目录才是仓库根，
> 选 `miniprogram/` 会让版本管理面板找不到仓库、看不到任何提交历史。
> 打包范围由 `miniprogramRoot` 限定，`tools/`、`data-source/`、`admin/`、`.workbuddy/` **不会**进小程序包。
> 本机设置放在仓库根的 `project.private.config.json`（已 gitignore）。
   测试号能跑本地模式，但**云开发必须正式 AppID** —— 测试号连 `wx.cloud` 都初始化不了。
4. 如提示「不校验合法域名」，在开发者工具里勾上（本地开发用；云开发路线本来就不走域名白名单）

> **为什么不需要备案域名？**
> 院校数据是构建期编译进包的静态模块，**查询与匹配离线可用**；
> 账号资料、内容补丁与反馈工单走**微信云开发**（`wx.cloud.callFunction`），
> 走的是微信自己的通道、不经过 `wx.request`，因此绕开了
> 「境外数据源需 ICP 备案域名 + 后台白名单」的限制。
>
> ⚠️ 但**运行期并非「零网络请求」** —— `loadContent()` 会拉一次 `GET /v1/content`，
> 取不到时静默回落到内置默认值。写提审材料时别沿用旧表述（见第七节）。

界面不再提供改线上文案的能力；如需恢复，请先确认这是有意的产品决定。

改完后台代码后的部署命令：

```bash
# 一条命令：同步静态页副本 → 暂存目录里部署 → 自动验证（不通过就非 0 退出）
bash tools/deploy-admin-function.sh

# 密钥不在本工作区时（本项目常用 git worktree，而 .admin-key 已 gitignore，
# 只存在于当年第一次部署的那个工作区）指过去即可 —— 不要复制密钥副本
ADMIN_KEY_FILE=<project-root>/admin/.admin-key \
  bash tools/deploy-admin-function.sh
```

⚠️ **不要手敲 `tcb fn deploy admin`**：项目根没有 `cloudbaserc.json` 时 CLI 会走「智能推测」，
**报「✔ 云函数部署成功！」并把控制台修改时间刷新到当前，线上却仍是旧代码**，全程没有任何报错。
脚本把「暂存目录 + 显式 runtime/handler + `--httpFn`」和三层验证（下回线上文件清单 / 真打线上接口 /
函数类型与打包范围）都固化了，别绕过它。

⚠️ 部署时 rc 里必须带上 `ADMIN_KEY_SHA256`，否则可能被清空 → 表现为「密钥正确也进不去后台（503 未配置）」。
脚本从本机密钥**现算摘要**带上去，并且带密钥的探测走 `curl -K -`（配置从 stdin 走），
**不让密钥进进程 argv**。

⚠️ `--httpFn` **必须带**（CLI 默认是 Event 型，漏了会把函数类型改掉 = 后台整站打不开）；
但**不要**带 `--path`：访问路径 `/admin` 首次部署时就创建了，重复创建会报 `Path is used`。

⚠️ 判「打包范围对不对」要看**下回来的文件清单顶层结构**，不看体积：
顶层若混进 `.git` / `README.md` / `.workbuddy` / `miniprogram` 才是打错了根。
（曾误以为「CodeSize 11 MB = 把整个项目打进去了」—— 实测 11 MB 里主要是云端装的
`wx-server-sdk` 及依赖，解压 6400+ 文件；体积不是判据。）

## 四、真机调试修正记录（重要，别改回去）

下面是历轮真机 / 用户报障暴露出来的问题，**每一条都写清根因，因为它们看起来
都像「小样式问题」，实际都是架构或真实性缺陷**，照着改回去一定会复发：

### 1. 图标完全不显示 → 不能用 SVG，必须用 PNG

- **根因**：v1 把 SVG 源码编成 base64 塞进 WXSS 的 `background-image`。
  开发者工具（Chromium 内核）里正常，**真机 WebView 不支持 CSS 背景图里的 SVG data URI**。
- **结论**：图标统一改为 **PNG data URI + `<image>` 组件**。
  图标路径取自 **lucide 官方图标库**（不再手写近似图形）。
- **注意**：`<icon name="star-line" color="line" />` 会去找 `star-line-line`，
  找不到时组件会回退到别名表，不会渲染空白。

### 2. 页面切换无动画

- **根因**：微信 **switchTab（标签页之间）本来就没有转场动画**，这是平台行为；
  而「匹配中 → 匹配结果」用的是 `redirectTo`，属硬替换、零动画。
- **结论**：内容区加 `page-in` 淡入上移、列表项错峰入场（见 app.wxss）。
  ⚠️ 动画只加在**内容容器**上，不加在 `.page` 根节点 ——
  根节点一旦有 `transform`，内部 `position: fixed` 的导航栏会退化成相对定位。

### 3. 登录直接显示出无关账号

- **根因**：本地适配器里写死了一个用户对象（含姓名邮箱），真机上就显示出来了。
  **这是编造用户身份，性质严重。**
- **结论**：本地模式只返回空档案 + `isLocal` 标记；
  昵称头像必须由用户通过 `chooseAvatar` / `nickname` 主动提供。
- **补充**：`wx.login` 是**静默**的（不弹窗），这是微信设计；
  头像昵称自 2022 年起不再由 `getUserProfile` 提供，必须用上述组件。

### 4. 没填数据却自带成绩

- **根因**：把设计稿里的演示数值（GPA 86 / 雅思 5.0 / AP 三门）当成了默认档案，
  用户什么都没填就"自带成绩"，还会据此算出匹配度 —— 等于凭空生成结论。
- **结论**：`content.defaultAcademic` 改为**空档案**；
  匹配前置校验「高中均分 + 语言成绩」，缺任一项则**整校不出分**
  （`match: null` / `tier: 'unknown'`），并引导去填写。

### 5. 匹配被包装成「AI 评估」

- **根因**：旧版匹配中页是**假进度**（随机涨到 92%）+ 假文案（「正在核验…」），
  实际只是本地毫秒级算术，没有任何 AI 参与。
- **结论**：拆成 4 个**真实阶段**，进度只在阶段真正完成时前进；
  AI 被放到真正的位置（生成个性化解读），且**如实标注来源**。

### 6. 首页首个入口无故高亮

- **根因**：把设计稿里「成绩匹配」的**按下态**当成了常态。
- **结论**：常态统一浅灰，按下时才变钴蓝（用 `hover-class`，真机更稳）。

### 7. 吉祥物看不出在动

- **根因**：只做了极轻微的呼吸，且只给匹配中页传了参数；
  而且方向就错了 —— Bloub 官方 measurements 明确写「静止态**不浮动**」。
- **结论**：按官方实测参数重做，`motion` 可选四种组合：

| motion | 用在哪 | 表现 |
|---|---|---|
| `idle` | 条款页 / 登录页 / 结果空态 | 视线漂移 + 不定时眨眼 + 0.5% 呼吸 |
| `search` | 匹配中 | 形体循环形变，**每次形变被一次眨眼遮住** |
| `celebrate` | 完成 | 短促两次压缩 |
| `none` | 列表缩略图等 | 完全静止 |

参数取自官方实测：静止眨眼 0.18s、形变前强制眨眼 0.2s、缓动 exponential ease-out（身体不过冲）。

### 8. 改个昵称就「变成已登录」了

- **现象**：未登录状态下打开个人资料页填了个昵称，返回账号管理页却出现「退出登录」按钮 ——
  用户从未登录过，也没有任何账号。
- **根因**：`utils/api.js` 的本地适配器 `user.updateProfile` 里写了
  `store.setSignedIn(true, next)` —— **顺手点亮登录态**。登录态本该只由 `login()` 负责。
- **结论**：改为保持当前登录态不变（`store.setSignedIn(store.isSignedIn(), next)`）。
  **「写数据」与「改登录态」是两件事，任何写入路径都不得顺手把用户标成已登录。**

### 9. 头像会变白 / 本机临时路径被存进了账号

- **现象 A**：设完头像，小程序重启后头像变白。
  根因：`bindchooseavatar` 回调给的是**临时文件路径**，重启即失效。
- **现象 B**：远端模式下换头像，换台设备就是一张裂图。
  根因：旧实现无论哪种模式都只做 `saveFile` 转存，然后把 `wxfile://...` 直接 PUT 进账号。
- **结论**：落地逻辑收敛到 `api.saveAvatar(tempPath)`，两种模式语义分开：
  远端走 `wx.uploadFile` / `wx.cloud.uploadFile` 拿永久地址（云存储落在 `avatar/`），
  本地才 `saveFile` 转存。**上传失败时不提交 avatarUrl**（宁可这次不改头像，
  也不给账号写一个别人解析不了的地址）；服务端 `handlers/user.js` 再拦一道，
  只接受 `https://` 与 `cloud://`。

### 10. 界面上写着「会同步到你的账号」，实际没同步

- **根因**：`GET/PUT /v1/user/profile` **从没登记进云函数的 ROUTES 表**，
  云开发路线上一直返回 501 → 客户端静默回落本地实现。
  功能不报错、不崩溃，只是**一个字节都没上云** —— 属于最难发现的一类假话。
- **结论**：端点补齐（`cloudfunctions/api/handlers/user.js`）。
  ⇒ **新增端点时顺带想一遍：页面上有没有哪句话，是「依赖它真的实现」才成立的。**
  同理，凡是前端文案里的承诺（同步、送达、已保存到某处），都必须有代码兜着。

### 11. 退出登录后头像/昵称还挂在账号页上

- **现象**（用户 2026-09-20 报）：点了「退出登录」，**头像与昵称仍在卡片上**，
  唯独「退出登录」按钮消失了 —— 界面同时在说「你是谁」和「你没登录」。
- **根因有两层，缺一不可**：
  1. **数据层**：本地适配器的 `user.profile` 压根不看登录态，直接返回 Storage 里
     缓存的用户对象。而云函数上的 `/v1/user/profile` 当时还没部署（见第 10 条）→
     501 → 客户端静默回落本地 → 登出后照样读得到身份。
  2. **视图层**：账号页的昵称/头像/徽标没有以登录态为闸门，数据层一旦漏出就直上屏幕。
- **结论**：本地实现与契约同语义 —— **未登录返回 `null`**、未登录写入 **401**
  （否则会出现「写进去了但读不出来」）；视图层再加一道 `signedIn` 闸门。
  **任何一层单独失守，身份都不该漏到屏幕上。**
  登出**不删**已填资料（`logoutConfirm` 承诺的是保留档案），重新登录即可恢复。

### 12. 「已保存」其实只写进了本机

- **根因**：`call()` 对未实现的云端端点会**静默回落到本地实现**（第 10 条），
  于是「运行模式是 remote」与「数据真的上了云」是两件事。
  若按 `api.mode()` 挑文案，云模式下就会把「写进本机」说成「已保存」。
- **结论**：判据只能是**返回值里的送达语义** —— 本地适配器恒带 `isLocal: true`
  （与反馈链路的 `delivered` 同一套约定），页面据此选「已保存」/「已保存到本机」。
  **别用运行模式猜数据去了哪里。**

### 13. 新页面没有返回键（漏了不报错）

- **现象**：新建「我的收藏」页时写成 `<nav-bar title="{{c.nav.favorites}}" />` ——
  编译通过、标题正常、所有测试全绿，**只是没有返回箭头**。
  真机上用户点进去之后，除了系统手势就没有任何出口。
- **根因**：`nav-bar` 的返回箭头**只在显式传 `back` 时才渲染**（`<view wx:if="{{back || backText}}">`），
  默认值是 `false`。这类缺陷不表现为「坏掉」，只表现为「少了一个东西」，
  而少掉的东西没有任何断言会去数。
- **结论**：**凡是 `navigateTo` 进去的二级页，必须显式给返回出口**：
  `back="{{true}}"` + `fallbackUrl`（没有历史栈时的兜底，如从分享卡片直达），
  或者 `back-text` 自定义取消。
  tab 页与启动页**不要**放飞箭头（无历史栈可回，是死 UI）。
- **守住它的断言**：`node tools/check-page-exits.js` —— 遍历 `app.json` 全部页面，
  逐页检查「非 tab、非启动页必须返回出口」「传了返回就必须有兜底落点」
  「启动页不许有返回箭头」「标题必须来自内容层」。
  ⚠️ 断言前会先剥掉 WXML 注释 —— 这些页面的注释里全是「返回」二字，
  不剥的话注释会把断言喂绿（写这个脚本时第一次就是这么写的）。

### 14. 同一句话画了两遍：多一个加号、多一行提示

- **现象**（用户 2026-09-23 截图报障）：匹配页课程卡右上角写成「**＋ ＋ 添加科目**」，
  卡内「没考国际课程也能申请，跳过本卡即可」**上下各出现一次**。
- **根因有两处，属同一类**：都是「两个来源各画一遍」，且**编译能过、没有任何断言会红**：
  1. `<icon name="plus">` 已经画了加号，内容层的 `addCourse` 又写成 `'+ 添加科目'`
     —— 加号由**图标 + 文字**两层各自贡献。加号是图形，**文案层不该带它**。
  2. 空态框 `.course-empty` 与卡底 `.card-desc` **共用同一句 `courseHint`**，
     且**都无条件渲染** → 列表为空时同屏出现两遍。两句各自都合理，只是必须互斥。
- **结论**：`addCourse` 定为 `'添加科目'`（加号只由图标负责）；卡底提示加
  `wx:if="{{courses.length}}"`，与空态框互斥。
  **凡是「同一句话出现两次」的报障，先找第二个渲染点，而不是改文案本身。**
- **守住它的断言**：`node tools/verify-match-page.js` 第 1.9 节 ——
  ①「添加科目」文案不得以 `+` / `＋` 开头，`.add` 区块内不得再出现字面加号；
  ②卡底 `courseHint` 必须受 `courses.length` 闸门控制（空态框则无条件存在）。
  另注：此类「多一份」缺陷与第 13 条同族 ——
  **少东西 / 多东西都不会让任何测试变红**（如 WXML 注释会把断言喂绿），
  只能靠针对性断言把渲染条件钉住。

### 15. 转发 / 朋友圈菜单置灰（漏了不报错，且不是备案问题）

- **现象**（用户 2026-10-11 报）：右上角「转发给朋友 / 分享到朋友圈」菜单整页置灰，点不动。
  第一反应是「没备案 / 没发布」—— 但**根因在代码层**：原 15 个页面**一个 `onShareAppMessage` 都没定义**。
- **根因**：微信官方 Page 文档原话「**只有定义了 onShareAppMessage，右上角菜单才会显示「转发」按钮**」。
  本项目 15 个页面此前全部没有这两个生命周期函数，于是菜单整页置灰，**与备案 / 审核状态无关**
  （那两件事影响的是「分享出去别人能否打开」，不是「菜单是否可选」）。
  ⚠️ 网上流传的「tabBar.list 加 `shareable` 字段」是**第三方未经验证的谣言**，官方属性表里没有这一项。
- **结论**：新增 `utils/share.js`（`withShare` / `pageRoute`），15 个页面 `Page({...})` 改为
  `Page(share.withShare({...}, { pageId }))`，由工具统一注入 `onShareAppMessage` / `onShareTimeline`；
  分享文案走内容层 `content.share`，落地页统一回首页（带 id 的页面不带 query）。
  **今后任何页面要接转发，一律走 `share.withShare`，不要自己手写 `onShareAppMessage`**，否则会被
  `tools/check-page-exits.js` 第 5 节拦下。
- **平台层仍需发正式版**：体验版 / 开发版分享出去，他人打开会提示「无权限」—— 这是微信平台限制，
  代码层修不了，必须发布正式版（v1.0.4 起代码已就绪，等发布即可）。
- **守住它的断言**：`node tools/check-page-exits.js` 第 5 节 —— 遍历全部页面，
  逐页检查是否注册了 `onShareAppMessage` / `onShareTimeline`（经 `share.withShare` 或自写）。
  ⚠️ 已反向验证：临时剥离某页注入后该页两条断言立即变红、其余不变，证明不是假绿。

## 五、两条架构铁律（改代码前必读）

### 1. 一切走 `utils/api.js`，不要绕过

页面**不直接**引用 `utils/store.js` 或 `data/`，一律通过 `api.xxx()`。
`api.js` 内置双适配器：

| 模式 | 触发 | 数据来源 |
|---|---|---|
| `local`（当前） | `request.CONFIG.baseUrl === ''` | 设备本地 + 内置院校数据 |
| `remote` | 填了 `baseUrl` | 按 `API接口契约.md` 实现的后端 |

切换只改一处：

```js
// miniprogram/utils/request.js
const CONFIG = { baseUrl: 'https://your-domain.com' };
```

页面代码零改动。只读接口（院校列表 / 详情 / 内容）在 remote 失败时会自动回落到本地数据。

### 2. 不许写死，文案与参数都放 `data/content.js`

页面上出现的每一个字、每一个列表、每一个阈值都从这里取。
后端 `GET /v1/content` 下发**补丁**（只含要改的字段）后按「对象递归合并、数组整体替换」覆盖，
因此**改文案、调匹配权重、开功能开关都不需要重新发版**。

| 类别 | 位置 | 改了要不要发版 |
|---|---|---|
| 页面文案 / 提示语 | `content.*` | 不需要 |
| 下拉枚举（国家 / 专业 / 体系） | `content.enums` | 不需要 |
| 功能入口与分组 | `content.functions.groups`、`content.home.features` | 不需要 |
| 匹配权重与分档阈值 | `content.matchConfig` | 不需要 |
| 功能开关 | `content.featureFlags` | 不需要 |
| 标签栏**页签增删** | `app.json` + `content.tabBar` | **需要**（小程序限制） |
| 新增页面 | `app.json` | **需要** |

> ⚠️ **「不需要重新发版」的前提是补丁真的发得出去**（2026-09-22 校订）：
> 内容补丁的**界面入口已从运营管理台移除**，`PUT /admin-api/content` 路由虽在、但当前没有界面。
> 也就是说，改完 `content.*` 要让它生效，眼下得走**改源码重新上传**这条路（或手工调那支 PUT 接口）。
> 上表描述的是**机制**（`GET /v1/content` 深合并确实存在），不是当前的操作路径 —— 别照着表格去找入口。
> 另：`matchConfig`（匹配权重 / 分档阈值）有一条更硬的限制 —— **服务端直接拒绝**后台发布它
> （算法口径变更需代码审核，见契约 4.10 拒绝清单），所以那一行从来没有真的走过后台。

**给已有页面加信息时，按这个顺序做**：
先补接口字段 → 再补 `content.js` 默认值 → 最后改页面绑定。
这样后端还没上线时，页面也能用内置默认值正常渲染。

## 七、合规要点

- **登录页不得在启动时强制跳转**。依据《小程序内用户帐号登录规范》，
  必须由用户主动触发，且提供「暂不登录，先浏览」出口 —— 本项目的 `pages/signin` 已按此实现。
- **协议同意页可以前置**（属《个人信息保护法》知情同意），当前启动路径为
  `条款页 → 首页`，不经过登录页。
- **域名备案只对自建后端（`baseUrl`）路线适用**。当前走的是微信云开发（`request.CONFIG.env`），
  调用不经过 `wx.request`，**不需要 ICP 备案、也不需要配置 request 合法域名**。
  将来若切换到自建后端，这一条才成为硬性前置条件。
- ⚠️ **运行期并非「零网络请求」**：`api.loadContent()` 会请求 `GET /v1/content` 拉内容补丁；
  **登录后成绩档案与收藏会同步到云端**（`/v1/academic/profile`、`/v1/favorites`，
  换设备登录时拉回来）；账号资料与反馈工单也走云函数。
  写提审材料与隐私说明时**不要**沿用旧版本的「运行期不发起任何网络请求」表述 ——
  那句在云开发路线下是假的。
  弱网 / 离线时内容层静默回落到内置默认值、成绩与收藏回落到**本机缓存**，
  因此「离线可用」这一条仍然成立。
